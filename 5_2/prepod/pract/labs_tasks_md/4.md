ЛАБОРАТОРНАЯ РАБОТА №4
Тема: Интерактивность и анимация на стороне клиента. Использование
JavaScript для управления DOM, событиями и анимацией элементов
веб-страницы.
Цель работы
Освоить базовый синтаксис JavaScript в контексте браузера.
Научиться находить элементы на странице, реагировать на действия
пользователя (клик, наведение, ввод в поле, загрузка страницы) и
программно менять классы, стили и содержимое. Применить минимум три
различных по приему анимации (через CSS-классы и/или Web Animations
API и/или requestAnimationFrame), не нарушая исходную верстку и
семантику HTML. Изучить принципы построения диаграмм состояний.
Задание кафедры
Взять готовую статическую страницу по варианту из лабораторной
работы №2 (тот же HTML/CSS и те же ресурсы) и добавить сценарии на
JavaScript так, чтобы страница демонстрировала осмысленное поведение:
анимации запускаются по событиям, состояние элементов меняется
предсказуемо, код читаем и сопровождается комментариями (можно
написать пояснение к коду отдельно) в местах нетривиальной логики.
Запрещено подключать фреймворки и библиотеки (React, Vue, jQuery и
т.п.): только нативный JavaScript и возможности браузера. Вариант
страницы — по номеру в списке группы, как в ЛР №2. Для полученной
анимированной страницы построить диаграмму состояний (например,
“проигрывается анимация 1”).
Требования к выполнению задания:
1. Объем и привязка к макету: Не менять структуру и внешний вид
страницы в состоянии «по умолчанию» так, чтобы она перестала
соответствовать макету из Figma; допускается добавление
небольших элементов управления (кнопки, переключатели), если
они согласованы с преподавателем или логично вписаны в блок
(например, «Показать ещё», «Запустить анимацию»).
2. Минимум три разных анимации, из них не менее двух должны
отличаться механизмом реализации, например: (а) смена/добавление
CSS-класса; (б) анимация через element.animate() (Web Animations
API); (в) покадровое обновление свойства (transform, opacity, offset) в
цикле requestAnimationFrame или короткий сценарий с setInterval,
после чего интервал обязательно очищается (clearInterval).
3. События: Не менее двух разных типов событий (например, click и
input, или mouseenter и scroll — на усмотрение варианта), при этом
хотя бы одна анимация должна запускаться по действию
пользователя, а не только при загрузке страницы.
4. Код: Один или несколько подключаемых файлов .js (подключение
через <script src="..." defer> в конце body или с корректным порядком
загрузки); без inline-обработчиков в разметке (атрибуты onclick и т.п.
не использовать). Имена переменных и функций осмысленные;
дублирование логики желательно минимизировать (вынести
повторяющиеся действия в функции).
5. Диаграмма состояний: на диаграмме должны присутствовать все
возможные состояния созданной страницы и корректные переходы
между ними.
6. Состав сдачи: Исходники HTML, CSS, JS и папка с ресурсами (если
не используются сторонние), отчет и диаграмма состояний; при
демонстрации — открытие index.html (или главного файла) в
браузере из локальной папки.
Требования к отчёту
Отчёт по лабораторной работе должен содержать следующие разделы:
1. Титульный лист
2. Цель работы
3. Задание кафедры
4. Краткая теоретическая информация по теме — DOM, события в
браузере, способы анимации (CSS + JS), отличие transition от
keyframes, идея requestAnimationFrame и Web Animations API (только
то, что использовано в работе).
5. Выполнение работы — скриншоты страницы до и после
взаимодействия (или серия кадров), фрагменты листинга HTML
(подключение скрипта, добавленные элементы, если есть), полный
или сокращенный листинг JS с пометками «здесь запускается
анимация 1…2…3», краткое описание сценария для каждого
варианта поведения.
