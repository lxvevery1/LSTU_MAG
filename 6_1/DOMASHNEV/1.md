Методологии:
1. Водопадная модель - четкая последовательность этапов - этапы двигаются друг за другом без возврата к
прежнему этапу.
Анализ (постановка задачи) - ТЗ ->
        Проектирование - Проект (тех проект) ->
            Реализация ->
                Внедрение -> Сопровождение

2. Развитием водопадной модели является спиральная модель
не можем в один цикл реализовать продукт, требуется несколько циклов.
В спиральной модели выделяется следующие итерации:
по спирали -> планирование - анализ рисков - проектирование (разработка) - внедрение
В спиральной есть этап анализа рисков.

MSF - представитель спиральной модели Microsoft Solutions Framework.

3. Инкрементная модель - хочется быстро вывести продукт на рынок - объем виден,
нужно начинать с малого продукта - функционал делится на модули.
Выстраивается последовательность из этих модулей и для каждого модуля выполняется
мини водопадная модель.
Основная идея - законченная функция.
Тут нет этапа анализа рисков.
Модель RUP - Rational Unified Process.

4. Итеративная модель - не режем продукт вертикальо по частям, а берем широко, но модели незаконченные.
Эти добавления происходят в виде итераций. Итераций меньше.

# Гибкие
5. AGILE - итерации маленькие, короткие и быстрые. Берется широко, но функционал небольшой
после каждого спринта должен быть функциональные продукт после релиза.
Итерация или спринт не берут кусочек продукта вертикально - берется функциональность и добавляется.
Когда используется гибкая методология - при маленькой команде, нет четкой постановки задачи, невозможно изначально
оценить размер продукта. Минимум документации (меньше объем работ).

6. SCRUM. Роли: свиньи и куры.
Свиньи - полностью вовлечены в работу - проводят собрание, назначает время.
Скрам мастер Модерирует процесс.
Руководитель проекта не являвется скрам мастером.
Владелец продукта - заинтересован в разработке продукта. Антагонист разрабов.
Отстаивает интересы пользователей продукта.
Тимлид выступает со стороны тимы. Отстаивает интеерсы команды.

Куры не задействованы в разработке, но они стей холдеры. Вовлечены в реализацию с точки зрения бизнеса.
Участввуют в некоторых частях скрама, не имеют права управлять разработкой.
Жизненный цикл скрам:
1. Совещание по планированию спринта.
2. Ежедневные встречи - скрамы. Задача: увидеть состояние участников вовремя.
3. 2 совещания подряд - рассказать курам результат
4. Ретроспективное участие внутри себя - как хорошо, что плохо, что надо изменить.
