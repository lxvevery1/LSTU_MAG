Ansible!

В ансибл есть 2 вида виртуалок:
    Manager OS.
    Target OS - управляемая.

    Для того чтобы вся тема управлялась на каждую таргет ос ставится агент.
    В случае с Ansible на таргете агент - питон + ssh вход (ключ) (нулевой агент)
    В менеджере стоит ансибл.
    В inventory (yaml) - список всех таргетов.
    Сами inventory могут быть разнесены на группы (серверный датацентр, южный дц) и роли.

    Описывается каким набором таргетов управляем со станции.

    Существует описание станций - плейбуки и роли.
    Это декларативное описание - на этой машине должен быть установлен такой то пакет.
    Затем запускается некая команда и ansible присоединяется к агенту: выполни команду -> собирается facts.
    он сам автоматически скачивает с таргета в каком состоянии он находится (есть ли пакет там или нет).
    Сравнивает таргет сетйт со стейтом из машины и определяет набор действий, которые надо совершить.
    Execute -> report.

    Не пишем что делать, а задаем только target.
    а ансибл сам определяет какие действия нужно совершить.

    первая проблема ансибл: нетривиальный язык с кучей нюансов.
    работает хорошо в теории - когда плейбуки написаны хорошо.
    сам ансибл поставляется в комплекте нескольких ролей и плейбуков.

    Императивный подход только на уровне diff между current state и target.
    проблема развертывания в среде OS - не просто писать package - с автоустановкой и настройкой нет возможности.
    package не решает вопрос dependencies.
    Есть стационарная зависимость.
    А есть динамическая.
    Давайте соберем сочлененный рантайм, предназначенный для развертывания в конкретной точке.
    Тут и появляется докер.
