виртуальные машины - как организовываются?

вм реалзуются благодаря гипервизору - он создает вм.
2 типа - на bare metal устанавливается гипервизор (нет ОС).
к числу таких гипервизоров - VMWare ESXI, XEN - первый тип - Hyper-V.
второй тип - когда устанавливатся ОС - линукс или виндовс.
Virtual Box, VMWare Workstation, в линуксе есть свои гипервизор - KVM (kernel virtual machine)
- модуль ядра линукс, который предосавляет API для создания и управления VM (no UI).
Когда на HOST OS запускается вм, запускается процесс - каждый процесс соотв. ядру виртуальной машины.

Чтобы вм азпустить, нужно иметь по которое будет его предоставлять.
В виртуал боксе испольуется продукт QEMU - quick emulator.
QEMU - для intel запускать программы другой архитектуры процессоров - эмулятор.
Он имеет массу режимов - режим системной виртуализации.
МОжно сказать что KVM создает среду - коробку. внутри которой может работать quest code.
quest code - работает на компьютере с CPU, MEM, I/O Controllers.
код общается с контроллерами и думает что общается с реальным железом.
Сам KVM не обеспечивает контроллеров.
Он обеспечивает адрессное пространство.
Чтобы обраттиться к контроллеру - нужна привелегированная инструкция.
прерывание передается QEMU. - эмулирует все устройства и всю среду которую видет quest code.
виртуалку создает модуль ядра. QEMU работает как юзер лэнд приложение - создай мне песочницу и все действия
песочницы передавай мне. qemu работает с виртуальными контроллерами.

физически для запуска под линусом вм - нужны KVM, QEMU, выдать длинную команду qemu with params.

запускать qemu можно прямо из щела (для джедаев).

Мощность виртуалок в том, что они управляют томами.
мапинг - какое устройстов на какой том - написано в дескрипторе.
Том - сама по себе сущность.
Устройство - вторая сущность.
Устройство соотв. тому.
как сделать тома?

есть volume - представлет из себя массив блоков (512б/4кб)
когда создаем том указывает кол-во блоков - нет файлов / каталогов.
только массив блоков.
заводим на диске хоста файл , кол-во блоков = размеру тома.
типы volume:

1. RAW FILE IMAGE - бывает .raw, .img или другой.
    очень простой способ - просто операцию i/o guest'а в read/write.
    а давайте не будем включать в image незадействованные блоки (никогда не было данных, реализуется на уровне драйвера).
    thick provision

2. появились сжатые форматы драйвера - vdi (v box), vhd (microsoft), vndk (vmware), .qcow2.
    спарс файлы - не все блоки заполнены (сначала маленький, по мере записи блоков увеличивается).
    guest не видит разницы между raw и vdi, в raw будет быстрее запись.
    .iso - связан с файловой системой iso9660 - CD / DVD / Blu-ray.
    легко расширяется на нескольо компьютеров благодаря сетевым файловым системам.

3. NFS, SAMBA, SMB/CIFS - qemu транслирует операцию в хост ос, хост ос на сервер - медленно, но работает.
    ZFS - продвинутая файловая система, позволяет распределить хранение на несколько компьютеров с защитой.
    если комп падает, информация не теряется.
    эти файлы можно положить на сетевую файловую систему

4. Block storage - partition (создать цельный диск),
