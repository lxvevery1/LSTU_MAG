Сервисы - объекты которыми управляют девопсы - размесить кучу сервисов (deploy).

Что такое сервис? Сервис - процесс или группа процессов ОС.
Что такое процесс - все сервисы работают поверх ОС (не эмбеддинг).
У OS выполнение в рамках процессов.
1. Любой сервис - процесс или группа процессов.

2. Они запускаются автономно (независимый запуск).
Если архитектура системы состоит из 20 сервисов, то они должны быть как-нибудь запущены.
Задача DevOps - установить ПО на узел + настроить (конфиги) + написать systemd unit.
3. Отсутствие UI - сервис запускается до пользователя.
4. Что делают процессы ОС? Исполняют код, манипулируют локальными файлами, ведут лог.
посколько UI нет, остается только ЛОГ.
5. И последний атрибут без которого сетевой сервис невозможен - к нему через Endpoint.

endpoint - SAAP service access point - логическая точка в сети к которой узлы
могут образаться. Есть API, которая позволяет ОС создавать, принимать входящие
соединения на сокет - сокет апи.

endpoint - организовання sap внутри приложения.

любой сервис, который хочет к кому то обратиться - tcp/udp, ip address, port - transport layer.
поверх транспортного уровня может функционировать сеансовый уроень - TLS + SSL.
Протокол уровня представления - http.
http расскахывает о том как посылать запросы и в каком виде посылать ответы - verb, pass, header, body.
Web-Socket - presentation protocol.
RPC - remote procedure call,
GRPC

Именно девопс должен знать как сконфигурировать тот или иной endpoint.

Контейнер - не обязан быть на физ. железе, может быть и на виртуалке.
На виртуалке ОС + установлен container engine.
Чем принципиально отличается контейнер - запускает приложение в самой ОС
(сервисы - прцоессы, использующие API одного и того же ядра (один page cache и
прочее))

процесс изолирован в индивидуальной песочнице - реализован в ядре ОС.
Запусти ОС в отдельном namespace, при этом внутри контейнера все dependencies.
Можно построить образ контейнера на одной машине и запустить на другой.
У контейнера свой ip-address.

Переходим в физику:
.Как завести у себя компьютер?
Купить в магазине ПК.
На каждом компьютере будет свое ПО.
Вся компьютерная инфраструктура делится на две части:
1. Датацентр - место жизни сервисов
2. workplaces - там где живут users - их персональное устройство

датацентров не так много.
workplace намного больше, следует сильный сдвиг в трудоемкости.
Поддерживать рабочие места сложнее - ОС, приложения, доступы.
Чтоы поддерживать workplace есть anykey'щики.
С такой схемой когда на workplace нужно установить много экземпляров нужен support.
workplace содержит только стандартное ПО - что в дистрибутиве.
Уменьшаем объем администрирования путем ограничения того что можно загрузить и установить.

Тонкий клиент - приложение удаленного терминала.
putty или rdp для входа в экран.
Само приложение в виртуалку (которая в датацентре) - один вариант тонкого клиента.
на тонком нет прикладного ПО в workplace, все в datacenter (например, браузер).

Отнять у людей шанс установить ПО тоже контр продуктивно - лучше держать внутри datacenter.

Datacenter - что это?
Компьюетры на которых работают сервисы - без userspace, без UI, чисто живые сервисы - это может быть полка или комната.
Огромные залы, уставленные стойками.

Что из комьютерного оборудования внутри компьютера должно присутствовать?
1. Там стоят HOSTS - это компьютеры на которых должно быть предусмотрено локальное хранилище - local storage.
Те самые диски + CPU + RAM.
2. Сетевая инфраструктура.
3. Внешний storage - второй компьютер для хранения данных HOSTS.

нет надежных устройств - кто-то когда то ломается, для того чтобы сохранять данные.
Для того чтобы данные сохранялись они должны лежать в независимых друг от друга местах.

Бэкапы надо делать регулярно - но потребуются, только если исходные носитель разрущится.
best practices - хранить в двух разных местах.
