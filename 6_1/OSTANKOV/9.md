Что делают со storage.
storage могут разбить на partition, а могут и не разбивать.
Внутри partition можно создать fs - file system.
но это шорткат, потому что внутри partition можно создать lvm - logical volume manager.
LVM - любой storage (disk or partition) отадть в качества pv - физического volume.
эти PV объединяются в VG ( volume group ), а внутри VG можно создавать сколько угодно LV.
SAN может быть нарезан на кучу логических томов.
LUN - logical unit number.

либо партиция, либо LV, либо диск образуют block level - уровень блоков с которыми работает все остальное.
над block level живет файловая система.
и над ней живет file level.
для ОС file level - хранилище.
для реальной работы этого недостаточно.
над file level этого недостаточно - над ним живут базы данных.
все 3 уровня block level, file level, logical data level - это stack persistance.

а еще умеет

физический бэкап читается только на той версии которая была в момент бэкапа.
Экспорт данных - копирует только данные, но самый медленный.
Проблемы и ограничения - безумно долго копировать.
Процедура восстановления долгая.
Когда случится авария 58 часов не получится 99.999.
есть более жесткая проблема - у вас система работает постоянно.
В момент бэкапа меняются данные.
начало бэкапа имеет более старую версию чем конец бэкапа.
Если в момент бэкапа блок был изменен, то там будет data inconsistency.

Если есть система снапшотов, то на уровне файловой системы делаем снапшот, делаем бэкап снапшота -
заполняет место на момент снапшота, no data inconsistency.

Есть еще проблема - проблема корректности бэкапа.
Восстановить бэкап - могут быть потеряны блоки.

Почему нельзя избежать бэкапа?
Бэкап помогает от повреждения носителя.
Но если админ сделал delete * rm -rf без бэкапа этого не починить.
Если файл зашифровал, то будет хранить данные в зашифованном виде.
Без бэкапа не будет data persistance.

борьба с катастрофами не обеспечивают восстановление - это последний шанс.
data renduncdacy применяют способы репликации.
данные хранят в специально созданных срдствах - базах данных (бэкап), брокера
сообщения (своя тема) и S3 (нативная аппликация + мультиверсионность).
