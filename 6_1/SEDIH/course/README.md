# Ключевые точки кисти: детекция на фото и видео в реальном времени

Курсовой проект: найти **21 ключевую точку кисти** (запястье и по 4 точки на
каждый из пяти пальцев) на изображении и видео, оценить качество метрикой
**PCK** и показать работу в реальном времени. Модель — готовый **MediaPipe**
(PoseLandmarker + HandLandmarker), датасет — **Voxel51/hand-keypoints**
(официальный тест CMU Panoptic Hand DB, 846 изображений).

## Результаты

PCK на 846 тестовых изображениях (нормировка `0.7 · head_size`, пропуск = промах):

| конфигурация | PCK@0.1 | PCK@0.2 | AUC | detection | p50, мс |
|---|---|---|---|---|---|
| кроп по GT-bbox (оракул) | 0.680 | **0.808** | 0.765 | 92.0 % | 130 |
| поза → ROI + полный кадр | 0.660 | **0.787** | 0.743 | 94.2 % | 522 |
| **поза → ROI (наш)** | 0.650 | **0.772** | 0.728 | 94.2 % | 380 |
| 2×2 тайла | 0.572 | 0.711 | 0.677 | 93.3 % | 399 |
| полный кадр, 720p | 0.540 | 0.645 | 0.613 | 83.1 % | 159 |
| полный кадр | 0.535 | 0.643 | 0.610 | 83.0 % | 152 |
| полный кадр, 480p | 0.527 | 0.630 | 0.598 | 81.4 % | 134 |

Главное: на мелких кистях (<5 % кадра) полный кадр даёт PCK@0.2 = 0.215,
а «поза → ROI» — **0.532** (в 2,5 раза лучше); на крупных (≥10 %) все варианты
почти равны (~0.92). То есть выигрыш даёт масштаб, в котором модель видит
кисть, а не замена модели. Пайплайн закрывает ~78 % разрыва между полным
кадром и «оракулом».

Полные таблицы, кривые, per-joint и CDF — `results/pck_summary.md` и
`results/figs/`. Калибровка ROI — `results/calibration.md`.

## Протокол PCK

Из статьи Simon et al., CVPR 2017 (авторы датасета):

> pixel distances in each example are normalized by 0.7 times the head size

То есть

```
PCK@α = доля точек, у которых ||pred − gt||₂ ≤ α · 0.7 · head_size
```

- основное число — **PCK@0.2**, дополнительно PCK@0.1, кривая по α ∈ [0.02, 0.5], AUC;
- пропущенная детекция = ошибка `+∞` по всем 21 точке (иначе метрика завышается);
- если найдено несколько кистей, для оценки берётся предсказание с ближайшим
  к GT запястьем (в датасете размечена одна рука);
- EPE в таблицах считается только по найденным точкам, промахи видны в колонке
  `detection`;
- разбивка: per-joint, по размеру кисти, left/right; в аннотациях есть флаг
  наличия MPII-разметки.

## Пайплайн

```
кадр → PoseLandmarker (lite, 512) → запястья/локти/плечи
     → квадратный ROI 3·bbox кисти вокруг запястья (letterbox)
     → HandLandmarker (512) → 21 точка в координатах кадра
     → [если пусто] проход по полному кадру 960
     → склейка дублей, EMA-сглаживание для видео
```

Почему так: кисть занимает ~9 % кадра (медиана), а порог PCK@0.2 — около
20 px. На полном кадре лендмаркер кисть часто не находит; на увеличенном
кропе — находит. Калибровка на 120 кадрах (`results/calibration.md`):
поза даёт запястье с ошибкой ≈0.17 bbox кисти, `bbox ≈ 0.45·плечи ≈
0.72·предплечье`, оптимум кропа ≈3–4.5 bbox; выбран компромисс 3 bbox.

Квадратность обязательна: на неквадратном ROI MediaPipe предупреждает
`NORM_RECT without IMAGE_DIMENSIONS` и возвращает искажённые координаты.

Опции:
- `ensemble_full=True` — дополнительный проход по полному кадру;
- `pose_every=N` — пересчёт позы раз в N кадров (realtime);
- `full_frame_fallback` — страховка, если ROI ничего не нашёл.

## Результаты по конфигурациям

Конфигурации в `src/eval_mediapipe.py`: `full`, `full720`, `full480`,
`tiles2`, `oracle`, `pose`, `pose_full`; запуск одной конфигурации —
`--configs pose`. Сводка пересобирается из сохранённых ошибок:
`--summarize-only` (без повторного инференса).

Почему `pose_full` не основной режим: правило «ближайшее запястье» в оценке
даёт ансамблю преимущество за счёт дополнительных гипотез, а в реальном
инференсе это лишние кисти на экране (колонка `лишних кистей`: 0.78 → 0.99)
и +37 % задержки. Поэтому по умолчанию `ensemble_full=False`; ансамбль
включается флагом `--ensemble`.

## Видео и realtime

```bash
# пост-рендер: H.264 через ffmpeg, звук исходника сохраняется
.venv/bin/python src/infer_video.py video.mp4 --width 960 -o out.mp4

# только быстрый превью-проход
.venv/bin/python src/infer_video.py video.mp4 --pose-every 3 --dump points.jsonl

# вебкамера: q — выход, s — скриншот, p — пауза, f — сглаживание, r — запись
.venv/bin/python src/demo_live.py
.venv/bin/python src/demo_live.py --fast --record demo.mp4
```

Замеры на CPU (4 ядра, без GPU), кадр 640×360: «поза + ROI» ≈350 мс/кадр
(≈3 FPS) при пересчёте позы каждый кадр; `--pose-every 3` даёт ≈300 мс, так
как основное время тратит HandLandmarker (два вызова на кадр), а не поза.
Режим «только полный кадр» — ≈110 мс (≈9 FPS), но с заметно худшим PCK.
На GPU обе модели ускоряются аппаратно.

## Ограничения

- правило «ближайшее запястье» даёт ансамблю небольшое преимущество за счёт
  дополнительных гипотез — основной результат поэтому у конфигурации `pose`;
- в датасете размечена одна рука, сценарии с несколькими людьми не оцениваются;
- без GPU интерактивность достигается уменьшением разрешения и пересчётом
  позы не каждый кадр;
- модель не дообучалась: цель — исследовать пайплайн и метрику.
